Unique rules: user.email is unique, and demand_signal has a unique key on (user_id, kind, place_key), so a repeated email for the same place creates no second row. place_key has no foreign key on purpose, because visitors can ask for towns that Arangly has not added. The searchable place data lives in a read-only SQLite file, not in MySQL, so it is not drawn here. Tables with a minor role show only key columns. The full DDL is in the migration files.
